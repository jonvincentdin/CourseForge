# DATABASE.md

## Database technology

PostgreSQL, accessed via **Drizzle ORM** (`drizzle-orm/postgres-js`),
schema-first, SQL migrations generated by `drizzle-kit`.

**Why Drizzle and not Prisma:** the product brief doesn't mandate an
ORM. Prisma's engine binaries need to download from
`binaries.prisma.sh` at install/generate time; that domain wasn't
reachable in the sandbox this milestone was built in, so it couldn't
be verified to work. Drizzle is pure TypeScript with no native binary
step, and its query builder was fully exercised (build + typecheck)
in that same constrained environment. Revisit only with a real reason
— see `DECISIONS.md`.

## Models/tables (current — Milestone 1 only)

### `user`
| Column | Type | Notes |
|---|---|---|
| id | uuid, PK | `defaultRandom()` |
| name | text, nullable | |
| email | text, unique, not null | lowercased before insert |
| email_verified | timestamp, nullable | reserved for future email verification flow; unused |
| image | text, nullable | |
| password_hash | text, nullable | bcrypt, 12 rounds; null for future OAuth-only accounts |
| created_at | timestamp, default now | |
| updated_at | timestamp, default now | not yet auto-updated on write — see Known Gaps |

### `account`, `session`, `verification_token`
Standard Auth.js `DrizzleAdapter` shape. Not hand-rolled — table
columns must match `@auth/drizzle-adapter`'s expectations exactly if
you touch them.

## Relationships

`account.user_id` → `user.id` (cascade delete)
`session.user_id` → `user.id` (cascade delete)

## Indexes

`user.email` has a unique constraint (and therefore an index). No
other indexes yet — nothing else to index.

## Storage

No file storage configured yet. Syllabus PDFs need a storage decision
(local disk vs. object storage) before Milestone 2 — see open question
in `DECISIONS.md`.

## Known gaps

- `user.updated_at` is not currently touched on update — add an
  `onUpdate` or handle it explicitly once there's a profile-edit flow.
- No migration has been generated or run yet in this environment (no
  reachable Postgres instance in the sandbox). Run `npm run db:generate`
  then `npm run db:migrate` against a real `DATABASE_URL` before first
  use.
